# План выполнения практики 1

Статус: ожидается облачная виртуальная машина и доступ по SSH. Развертывание и проверки не выполнялись.

Цель: самостоятельно развернуть LAMP и WordPress на публичной виртуальной машине, показать удаленное управление с macOS и подготовить отчет.

## Подготовка со стороны студента

- [ ] Зарегистрироваться у облачного провайдера и подключить оплату. HOSTKEY рассматривается как вариант; провайдер и тариф пока не выбраны.
- [ ] Заказать чистую VPS: Ubuntu 24.04 LTS, x86_64, 2 vCPU, 2 ГБ RAM, от 20 ГБ диска, публичный IPv4. Не заказывать готовый WordPress или панель управления.
- [ ] Добавить публичный SSH-ключ с Mac на сервер. Приватный ключ хранить локально, не отправлять в чат и не добавлять в Git.
- [ ] Передать агенту IP, SSH-порт, имя пользователя с root/sudo и локальный путь к приватному ключу. Доступы и адрес сервера в этот файл не записывать.
- [ ] Сохранить скриншот созданной VM в кабинете провайдера без платежных данных и секретов.

## Выполнение после получения доступа

- [ ] Подключиться с Mac по SSH; зафиксировать ОС, имя машины и успешное удаленное управление.
- [ ] Обновить Ubuntu, настроить пользователя с sudo и вход по ключу. Проверить новый вход до отключения исходного способа доступа.
- [ ] Настроить firewall: SSH с текущего публичного IP студента, HTTP для внешнего доступа. Базу данных наружу не открывать.
- [ ] Установить Apache, MySQL и PHP непосредственно на VM, без Docker.
- [ ] Проверить работу Apache, выполнение PHP и запрос к MySQL; сохранить доказательства, затем удалить диагностическую PHP-страницу.
- [ ] Создать отдельную БД и пользователя WordPress с доступом только к этой БД.
- [ ] Установить актуальную совместимую версию WordPress из официального источника.
- [ ] Завершить первоначальную настройку через SSH-туннель; создать администратора и тестовую публикацию. Публичные URL сайта настроить на адрес VM.
- [ ] Ограничить доступ к администрированию WordPress и входу в него SSH-туннелем; проверить публичную доступность сайта.
- [ ] Проверить автозапуск служб и доступность сайта после перезагрузки VM.

## Результат и сдача

- [ ] Подготовить REPORT.md в этой папке: провайдер, конфигурация VM, команды, версии компонентов и фактические результаты проверок.
- [ ] Сохранить собственные скриншоты регистрации/VM, SSH, LAMP и WordPress непосредственно в этой папке. Для новых индивидуальных результатов использовать БабушкинМВ в имени.
- [ ] Не включать пароли, приватные ключи, токены и платежные данные в отчет, скриншоты или Git.
- [ ] Использовать материалы Машкина из Downloads/Telegram Desktop/University только как примеры, не как доказательства собственного выполнения.
- [ ] Студенту загрузить результат в Moodle и продемонстрировать работу преподавателю. Сдача агентом не предполагается.
- [ ] Сохранить VM до подтверждения сдачи. Удаление VM, дисков и других оплачиваемых ресурсов согласовать отдельно.

## Критерии готовности и ограничения

- SSH с Mac работает по ключу; Apache и MySQL запускаются автоматически.
- PHP выполняется, приложение подключается к БД, WordPress показывает тестовую публикацию из внешней сети.
- После перезагрузки сервер сохраняет работоспособность; отчет содержит собственные доказательства выполнения.
- Домен, Docker, плагины WordPress и автоматизация развертывания в базовый объем не входят.
- По сохраненному TASK.md техническая часть дает до 18 баллов; после 11 октября бонус за срок равен 0. Фактическую оценку выставляет преподаватель.
- Тариф, доступность выбранной ОС и текущее окружение сервера проверить перед выполнением. Работа оплачиваемых ресурсов может продолжать тарифицироваться после остановки VM.
