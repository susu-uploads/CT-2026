# Практика 4: Swarm и CSV TOP-N

## Локально

- [x] Создать FastAPI API, HTML-форму и фоновый TOP-N на RQ.
- [x] Использовать Redis для очереди, CSV и результатов, TTL 3600 секунд после завершения.
- [x] Проверить CSV, BOM, числовую сортировку, равные значения и ограничения.
- [x] Проверить общий лимит очереди конкурентными запросами при остановленных worker.
- [x] Подготовить Compose с двумя worker и конфигурации Swarm/registry TLS.
- [x] Проверить отказ Redis, потерю worker, масштабирование 1 → 2 и сохранность результата при пересоздании.
- [x] Сохранить фактические результаты, журналы и скриншоты.

## Облако — ожидает три VPS и SSH

- [ ] Получить SSH-доступ к manager и двум worker; приватные ключи в чат и Git не передавать.
- [ ] Проверить Ubuntu 24.04 x86_64, ресурсы, приватную сеть и свободные порты.
- [ ] Установить Docker Engine и Compose на всех узлах, сохранить предыдущие практики.
- [ ] Настроить закрытые межузловые порты и публичные 8084/8085.
- [ ] Создать Swarm: manager и два Ready/Active worker.
- [ ] Создать TLS CA и registry-сертификат, установить доверие на каждом узле.
- [ ] Запустить registry на manager с volume; подтвердить доступ из кластера и недоступность извне.
- [ ] Собрать AMD64, передать архив по SSH, сверить SHA-256 и опубликовать образ в registry.
- [ ] Проверить docker pull образа на каждом worker.
- [ ] Развернуть nginx с двумя репликами на разных worker и показать публичный доступ на 8084.
- [ ] Развернуть приложение на 8085; показать API 1 → 2 → 4 → 2 и worker 1 → 2.
- [ ] Повторить CSV/API-тесты с Mac, проверить отказы и сохранность результата.
- [ ] Проверить WordPress и практики 2–3, сохранить облачные доказательства в REPORT.md.
- [ ] Студенту сдать основную и дополнительную части преподавателю.

FastAPI выбран вместо Flask по указанию студента. Принятие замены не подтверждено. Локальный Compose не является доказательством облачного Swarm. Авторизация пользователей и отказоустойчивость manager/Redis не входят в объем. Удаление ресурсов согласовать отдельно.
